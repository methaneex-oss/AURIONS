# AURIONS — Non-Command Event Ingress and Internal Producer Trigger Matrix

**Status:** Proposed engineering contract; not runtime-validated or owner-accepted.  
**Scope:** The 23 non-command events outside the Action Gateway's 15-event lifecycle matrix. No public command is invented for platform, worker, sync, retention, governance or internal subsystem transitions.

## 1. Trigger contracts

| Event | Producer origin | Exact trigger condition | Owner transition |
|---|---|---|---|
| `representation.revised.v1` | owning_domain_internal_transition | Emitted when the Representation subsystem receives a new source observation/evidence item or transformation result, validates provenance and owner scope, and commits a successor representation revision against the expected current revision. | Append a successor aggregate revision using optimistic concurrency; preserve prior and contradictory evidence. |
| `capability.revoked.v1` | platform_provider_ingress | Emitted when a trusted platform/provider ingress reports revocation for the exact provider identity and descriptor version; the adapter authenticates the source and verifies descriptor identity before recording the revocation. | Mark the exact descriptor revoked and invalidate dependent plans/caches; queued or in-flight operations are separately blocked/reconciled. |
| `memory.recorded.v1` | memory_consolidation | Emitted when the memory-consolidation worker completes an owner-scoped memory record/link after validating source provenance, retention classification and the destination memory revision; the memory record and event/outbox commit atomically. | Append owner-scoped memory record/link with provenance and retention classification. |
| `permission.evaluated.v1` | governance_evaluator | Emitted when the governance evaluator computes effective platform permission for the exact app/package, operation and target at the final pre-dispatch authorization boundary; it records the result and source evidence. This is not emitted by a read-only query. | Record current effective platform permission and evidence; evaluation never grants or extends permission. |
| `approval.decided.v1` | owner_governance_interface | Emitted when the authenticated owner-governance interface returns a signed/validated decision bound to one approval request ID, exact operation digest, owner session, one-time nonce and expiry; governance verifies identity, scope and replay before recording the decision. | `outcome.observed.v1` | observation_ingress | Emitted when an independent observation ingress commits postcondition evidence for an exact operation/objective from a source distinct from the provider receipt; provenance, observed time, scope and limitations are validated before append. | Append independently observed outcome evidence with unresolved effects and attribution uncertainty; provider receipt alone is insufficient. |
| `learning.update.accepted.v1` | learning_supervisor | Emitted when the Learning supervisor consumes an authenticated owner/governance acceptance decision bound to the exact quarantined learning-candidate digest, evaluation protocol, baseline and held-out results; it records acceptance only after all required gates pass. | `learning.experiment.completed.v1` | learning_supervisor | Emitted when the Learning supervisor consumes a terminal worker-job result, verifies job/attempt identity, input/config/code/data hashes, budget/deadline and artifact manifest, then commits the experiment completion record. | `self_model.updated.v1` | self_model_manager | Emitted when the Self-model manager commits a successor active self-model revision only after an explicit governance acceptance for the exact proposed revision, evidence set and expected predecessor revision; stale or model-generated self-approval is rejected. | Append an evidence-backed active self-model revision after its acceptance gate; no permission, authority or capability grant follows. |
| `sync.change.exported.v1` | sync_engine | Emitted when the Synchronization engine selects a locally committed owner-scoped change after export authorization, classification and policy checks, then persists an immutable outbound envelope/digest and export ledger. | `sync.change.applied.v1` | sync_engine | Emitted when the Synchronization engine receives a remote envelope, verifies peer identity/signature, owner scope, schema version, classification, causation and expected aggregate revision, then atomically applies the idempotent change and event/outbox. | Apply an owner-scoped, version-checked change idempotently; preserve source and causation lineage. |
| `sync.tombstone.applied.v1` | sync_engine | Emitted when the Synchronization engine validates an authorized deletion tombstone and applies it at the owning aggregate sequence before later changes; replay and restore consult the tombstone before accepting content. | Apply deletion tombstone before later changes; deleted content must not be resurrected by replay. |
| `sync.conflict.detected.v1` | sync_engine | Emitted when the Synchronization engine receives a valid remote revision whose base/expected revision conflicts with the current local aggregate; it persists both source revisions and an unresolved conflict record without selecting a winner. | Persist both conflicting revisions and mark unresolved; do not silently choose last writer. |
| `sync.conflict.resolved.v1` | sync_engine | Emitted when the Synchronization engine receives an authenticated owner-authorized resolution bound to the exact conflict ID and both source revisions, validates the resolution rationale and expected conflict revision, then appends the resolution. | Append explicit authorized resolution while retaining both source revisions and resolution rationale. |
| `artifact.registered.v1` | artifact_registry | Emitted when the Artifact registry validates an immutable manifest's content digest, provenance, owner, classification, format, size and storage reference, then commits the manifest and registration event atomically. Registration is not trust or activation. | Register immutable artifact digest, provenance and classification; registration is not trust or activation. |
| `artifact.quarantined.v1` | artifact_registry | Emitted when the Artifact registry receives failed signature/provenance/format/policy validation or untrusted worker output and atomically marks the exact artifact revision quarantined while preserving forensic metadata. | Mark artifact unavailable to runtime consumers pending validation; preserve forensic metadata. |
| `artifact.deleted.v1` | artifact_registry | Emitted when the Artifact registry completes deletion only after retention policy permits it, required owning stores acknowledge tombstones, content references are removed, and restore/sync replay cannot resurrect the artifact. | Record tombstone/deletion completion and verify retention obligations; replay cannot resurrect the artifact. |
| `disclosure.recorded.v1` | egress_governance | Emitted when the egress-governance boundary releases an exact outbound data digest only after validating recipient, purpose, data classes, owner authorization and approval reference; it appends the disclosure audit record atomically with the release ledger. | Append an exact disclosure audit record with recipient, purpose, data classes and approval reference. |
| `retention.deletion.requested.v1` | retention_worker | Emitted when the Retention worker accepts an authenticated owner-scoped deletion request after policy/scope validation, creates a durable deletion job and records the request before contacting each owning store. | Persist scoped deletion request and policy basis; deletion is pending until all owning stores acknowledge. |
| `retention.deletion.completed.v1` | retention_worker | Emitted when the Retention worker confirms every required owning store has acknowledged deletion/tombstone state and restore/sync safeguards prevent resurrection; partial acknowledgement remains pending or failed. | Persist completion evidence/tombstones across required stores and ensure restore/sync cannot resurrect deleted data. |
| `worker.job.progressed.v1` | worker_supervisor | Emitted when the Worker supervisor receives a progress checkpoint from the isolated worker, verifies job/attempt identity and resource budget, and persists the checkpoint. | Append bounded progress checkpoint; job remains non-terminal and output remains quarantined. |
| `worker.job.completed.v1` | worker_supervisor | Emitted when the Worker supervisor receives a terminal success result, verifies job/attempt identity, deadline, resource budget and output manifest/digests, then stores outputs as untrusted/quarantined artifacts before completion. | Persist worker result manifest as untrusted/quarantined output; completion does not accept or activate a candidate. |
| `worker.job.failed.v1` | worker_supervisor | Emitted when the Worker supervisor receives a terminal worker failure, deadline expiry or crash report, records the exact attempt/error and quarantines any partial artifacts. | Persist worker failure and partial-artifact quarantine; no partial result becomes active. |

## 2. Non-command producer invariants

- A non-command producer is a trusted internal subsystem or authenticated ingress, not a model-generated instruction or arbitrary client event.
- The ingress/worker/provider identity, owner scope, event schema version and source evidence must be validated before commit.
- Producer origin is not a public API command and does not create command dispatch permission.
- Event, aggregate mutation and owning-store outbox commit atomically. Cross-store workflows use durable saga IDs and reconciliation, not distributed ACID assumptions.
- Unknown, stale, replayed, unauthenticated or cross-owner ingress is rejected or quarantined; it cannot mutate a protected aggregate.
- For learning acceptance and self-model activation, the event trigger requires explicit owner/governance acceptance. This matrix does not add the missing public acceptance/activation command or merge learning updates with evolution activation.

## 3. Remaining implementation boundary

These 23 triggers are specified proposals. They require owner review, implementation, exact event-specific positive/negative acceptance tests, restart/replay/concurrency/fault execution and independent review. All events remain design-only/non-dispatchable until those gates pass.
